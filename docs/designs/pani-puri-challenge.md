## Problem Statement
A wedding chaat stall runs a live pani puri eating contest. One laptop, mirrored over HDMI to a 1920x1080 TV, has to be the crowd display, timer, counter and leaderboard all night. One operator/referee runs it from the keyboard while a queue of guests waits. Counting has to be fast, fair and arguable-free.

## What Makes This Cool
The TV shows a giant 420px count with a live face-tracked mouth overlay, and a "Bite spotted!" banner pops the instant the camera thinks a puri went in. The referee taps Space and the ding fires. It feels like a game show, runs fully offline, and no video ever leaves the laptop.

## Constraints
- Visual source of truth: Design canvas https://claude.ai/code/artifact/a11882ba-97e9-4c74-ac93-0bd68c03f250 (4 artboards + 4 sticky notes).
- Vite + vanilla TypeScript, no framework, no backend, no accounts.
- Palette: ground #1B0E2B, panel #2A1540, marigold #FFB627, chilli #E8432F, chutney #4CC27A, cream #FFF4DC. Titan One display, Rubik body.
- Crowd text >= 28px, count 420px, timer 140px, 48px TV safe margin. Operator strip small (20-24px).
- Every referee action has a hotkey: Enter, Space, X, +, -, P, Esc, F, S.
- Real buttons/inputs/labels, keyboard reachable, 4.5:1 contrast.
- Webcam-to-count latency < 150ms, measured and shown in Setup.

## Premises (agreed)
1. Timer is 140px (the blue note's 200px is stale; spec and Live artboard say 140).
2. MediaPipe WASM + `face_landmarker.task` + `hand_landmarker.task` are vendored into `public/mediapipe/` by `npm run fetch-models` (postinstall). No CDN calls at runtime. Service worker precaches shell + models.
3. "Too dark" = face-found rate < 50% over the last 2s OR mean luma < 45/255 (sampled from a 32x24 downscale). Face Landmarker exposes no per-face score.
4. Hand check: fingertip within 80px of mouth center in 640x480 frame space, scaled by (face width / 200px reference).
5. Baseline from the 3-2-1 countdown guards the close threshold: close = max(close, baseline + 0.05). Open stays absolute.
6. Every finished round is stored; TV shows top 10; duplicate names allowed. Enables CSV export, Fix score, Discard.
7. v1 answers to the pink note: a bite is a bite, first name only, round length 15-180s in Setup, prizes handled offline.

## Approaches Considered
- A) Main-thread minimal: rejected, breaks worker/offline spec and risks timer stutter.
- C) Camera as hype only: rejected, drops Auto mode the spec requires.

## Recommended Approach: B) Spec-faithful, layered

Module layout:
```
src/
  main.ts            boot, view switching, hotkeys
  store.ts           single app state + localStorage persistence (settings, results, round)
  round.ts           pure RoundMachine: IDLE -> ARMING -> LIVE <-> PAUSED -> BUZZER -> RESULT
  detector.ts        pure BiteDetector: ratio stream -> candidates (thresholds, 1.2s window, cooldown, hand gate)
  vision/
    camera.ts        getUserMedia 640x480@30, frame pump (createImageBitmap -> worker, transfer)
    worker.ts        FaceLandmarker + HandLandmarker (GPU delegate, CPU fallback), returns ratio, mouth center, face width, hand distance, luma
    client.ts        typed worker RPC, latency tracking (capture ts -> result ts)
  audio.ts           Web Audio ding + buzzer, mute
  views/idle.ts live.ts result.ts setup.ts   render from state into the canvas markup
  styles.css         tokens + artboard styles
public/sw.js         cache-first for /mediapipe/*, stale-while-revalidate shell
scripts/fetch-models.mjs
```

Key behaviors:
- Detection: ratio = dist(13,14) / dist(61,291). Candidate when ratio > open then < close within 1.2s, >= cooldown since last candidate, and (if hand gate on) hand near mouth within the 600ms before the open crossing.
- Modes: Hybrid (default) shows the banner; Space confirms, X rejects, optional auto-confirm after N s. Auto counts candidates directly. Manual ignores candidates. +/-1 always works.
- Round: ARMING runs the 3-2-1 and captures the baseline. BUZZER gives the last pending candidate a 1.5s grace window. RESULT auto-returns to IDLE after 20s or on Enter. Face lost > 3s in LIVE shows a "Step back in" banner; the timer keeps running.
- Timing is wall-clock based (`endsAt` timestamp), so a refresh mid-round restores the remaining time from localStorage, and pause stores the remaining ms.
- Latency = performance.now() at frame capture to performance.now() when the candidate is emitted in the main thread; Setup shows p50/p95 over the last 100 frames.
- Fullscreen requested on Start (Enter is a user gesture) and on F.
- Privacy: frames are only transferred to the in-page worker. No MediaRecorder, no network, no storage of images.

## Open Questions
- Is the stall laptop's WebGL available inside workers (Chrome yes, Safari varies)? CPU fallback covers it; latency must be re-measured on the real machine.
- Leaderboard auto-scroll beyond 10: not needed in v1 since only the top 10 are shown.

## Success Criteria
- Setup shows live mouth meter with both thresholds, and p95 latency < 150ms on the stall laptop.
- Full round loop works keyboard-only: type name, Enter, 3-2-1, count, buzzer, result, back to idle.
- Refresh during LIVE resumes with correct time and count.
- Pulling the network cable after first load: app and models still load.
- Unit tests pass for detector (threshold crossing, window, cooldown, hand gate, baseline guard) and round machine (transitions, pause math, grace, recovery).

## Distribution Plan
Runs locally on the stall laptop: `npm install` (fetches models), `npm run build && npm run preview`, open in Chrome, press F. No hosting needed.
